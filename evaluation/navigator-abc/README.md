# navigator-abc — 單輪 vs. 同 prompt 雙角色 vs. 導航取證的 A/B/C 實驗（D71），與只重測 B 的單臂實測（D73 的 B2、D74 的 B3、D75 的 B4／B4b）

五批紀錄在同一個 `runs/`：`C-*`、`A-*`、`B-*` 是 D71 的同期 A/B/C（45 次）；`B2-*` 是 D73 只重測改良取證後的 B（15 次）；`B3-*` 是 D74 再加涵蓋判定與結構化證據分析後的 B（15 次）；`B4-*` 是 D75 加事實核對與確定性修正、摘要驗證後的 B（15 次），`B4b-*` 是修正器修復後的重跑（15 次）；`*-summaries.json` 是各批摘要驗證的紀錄。`analyse.py` 與 `answers.md` 涵蓋全部。

問題：D69 的條件修正只對檢查看得到的錯有效；D70 顯示模型能初步定位「要看哪一節、哪個表」。使用者提出假設：先讓模型當 **Navigator** 指出證據位置、再當 **Analyst** 依證據分析，可能比單輪更完整、更正確；並要求分離兩個變因——**角色分工本身**（A 對 C）與**中途重新取證**（B 對 A）。ADR 0009。

## 要誠實說的

- **三次是初步探索**，不宣稱統計顯著；A 比 C 多 2 次通過全在 Q2，差距在三次內可被一次隨機波動抵銷。
- **Q1 的失敗是入庫時的章節摘要寫錯**，三臂共用同一份摘要，與回答模式無關；D69 那批的摘要沒有這句、Q1 三臂 3/3。Q1 的品質取決於摘要工作那一次生成，回答端的核對能抓到但不能修。
- **人工判定由 AI 做**，逐格對過 `paper-structure.json` 的 Table 1／Table 2 與 `graphrag-key-facts.md`；使用者抽查待補。三次「無錯誤但必要內容不足」（A-Q3-2、B-Q3-2、B-G2-2）若使用者認為應算通過，A 為 8/15、B 7/15、C 5/15。
- **B 的多餘證據比例 86%**（73/85）：地圖只到章節層級，一節 6 頁就取前 8 塊；預算先到先得，後面的計畫項（往往是真正需要的附錄表）被排除；沒有依問題相關度篩選。這是機制設計的問題，不是模型的問題（計畫 85 條全部定位到）。
- **B 的事實性錯誤比 C 多**（6 次對 2 次）：拿到表格切塊後模型寫更多數字（B-Q2-3 32 個、B-Q3-3 25 個），對的多、錯的也多；對 Demo 而言「多寫一個錯的數字」比「少寫一個對的數字」更傷。
