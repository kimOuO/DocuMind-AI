# revision-ab — 單輪 vs. 條件式驗證導向修正的 A/B 實驗（D69）

問題：確定性檢查能標出回答的錯誤，卻改不了回答。D69 允許在檢查觸發時再呼叫模型一次，把初稿與檢查結果交回去修正（最多兩次呼叫，實驗模式、預設關閉，ADR 0008）。這個實驗回答一件事：**第二輪修正是否真的改善最終回答，改善是否值得多一倍的時間與 token**。

## 設計

| 臂 | 設定 | 說明 |
|---|---|---|
| A 單輪 | `ANSWER_REVISION=false` | 現行預設：一次串流呼叫＋檢查標示 |
| B 條件修正 | `ANSWER_REVISION=true` | 初稿不顯示；hard／soft 觸發才再呼叫一次；修正稿重檢；依嚴重程度選最終稿 |
| C 永遠修正 | `ANSWER_REVISION=true`、`REVISION_ALWAYS=true` | 研究對照，只跑 Q3：觸發看不到的錯誤（方向、缺漏）修正會不會改善 |

- **同批問題、同文件、同設定、同期執行**：三臂在同一次 `pytest` 中跑完，文件各上傳一次、同一個 index，模型 qwen3:32b、Top-K 5、切塊 400／80 不變；每題用 `document_ids` 鎖定在它的文件，證據與單篇文件時相同。
- **問題**：Q1 全文摘要、Q2 LightRAG vs GraphRAG、Q3 消融實驗（各 3 次）；FACT 一般事實題（1 次）；NOANS 無答案題（1 次，應在檢索前被拒）；G1、G2 第二篇論文（Graph RAG，arXiv:2404.16130v2）的表格比較題（各 2 次）。標準答案：`../ground-truth/key-facts.md`、`graphrag-key-facts.md`，只用於人工評測、不進 prompt。
- **紀錄**：每次執行一個 `runs/<臂>-<題>-<次>.json`：設定、階段、來源、最終回答、`done`（含初稿與修正稿全文、觸發、選擇與理由）、每筆 LLM 呼叫的 tokens 與時間、端到端秒數。沒有個人資料，內容只涉及兩篇公開論文。
- **評測**：人工依 key-facts 逐句判每個候選答案（初稿、修正稿、最終稿）的事實正確性、數字歸屬、引用支持、缺漏；自動檢測的輸出另列。指標：最終通過率、修復率（初稿有錯→最終無錯）、新增錯誤率（修正稿出現初稿沒有的錯）、觸發率、token 與延遲、每次呼叫 10K 合規。
- **執行**：`pytest -m llm tests/integration/test_revision_ab_real.py -s`（環境變數 `AB_ARMS`、`AB_QUESTIONS`、`AB_RUNS` 可縮小範圍）。D68 的九份回答是歷史參考（`../answer-checks/`、`../number-check/`），不混入本實驗的比較。

## 兩篇論文上檢查器的差別（事先知道的事）

LightRAG 論文的 Table 1、Table 2 被切成表格切塊，數字標籤核對與全稱宣稱核對會啟動；Graph RAG 論文的 Table 2、Table 6 現有表格偵測沒抓到（版面不同），這兩類核對在 G1、G2 上不會啟動，只剩數字存在性、引用可疑與無效引用。不為第二篇論文加規則；這正是泛化測試要看的。

### 要誠實說的

- **B 臂 Q1 的三次觸發都是核對誤報**：句子「outperforms … such as NaiveRAG, RQ-RAG, HyDE, and GraphRAG in most evaluation dimensions, with win rates up to 86.4% in Diversity」被在「, and」切成子句，GraphRAG 變成第二個子句唯一的方法名，86.4% 就被判成 GraphRAG 的。修正稿把對照方寫明（「compared to NaiveRAG」），文字沒有變差，但這三次第二輪是白花的。清單連接詞與子句連接詞的區分是核對器的已知限制，A 臂的三份 Q1 剛好沒用這個句型。
- **Q3 是條件修正幫不上的題**：三次初稿都沒有觸發，最終與單輪相同；真正的錯（定義寫反、方向、A6 缺）檢查看不到。永遠修正只在 1/3 次修到一個真錯，另兩次模型重寫出幾乎相同的文字，連方向錯都原樣保留。
- **G1 的失敗與修正無關**，是路由關鍵字規則把內容題（community summaries）當成摘要題，兩臂相同；要另開決策處理。
- **G2 兩臂都沒拿到標準答案要的第 26 頁**，是檢索的限制；兩臂都沒編造，B 臂還明說來源沒有。
- 人工核對由 AI 做、使用者抽查；C-Q3-2 的初稿有 128 個數字，逐格對過。

### 結論

條件修正對**引用錯配**有效（Q2 修復 3/3、無新增錯誤、通過率 0/3 → 2/3），對**數字標籤錯**在 C 臂證明能修（1/1），對 Q3 現有的錯誤型態無效（沒有觸發），而核對誤報會直接變成白花的第二輪（Q1 3/3）。成本是觸發題 2.3–2.9 倍時間、2.1–2.3 倍 tokens，且實驗模式沒有即時串流。是否用於 Demo 由使用者決定；數據支持的說法是：**開啟後 Q2 更可能通過，Q1、Q3 不變，每題平均多等 20–35 秒**。
