# 專案文件

## 內容

| 資料夾 | 內容 |
|---|---|
| `02-specs/` | 平台規格，已確認並凍結 |
| `03-decisions/` | 架構決策紀錄：一個技術選擇一篇，寫明考慮過的選項、決定與後果 |

### 規格怎麼讀

| 想知道什麼 | 看哪裡 |
|---|---|
| 要做什麼、怎樣算完成 | `02-specs/01-requirements.md`：需求、階段與里程碑、62 條驗收條件 |
| 系統怎麼設計 | `02-specs/02-architecture.md`：架構、登入安全、入庫、Token 預算、切塊、檢索、摘要、評測 |
| API、資料表、環境變數 | `02-specs/03-interfaces.md` |
| 使用者實際怎麼用、系統該怎麼反應 | `02-specs/04-use-cases.md`：19 個情境 |

規格在需求與設計階段結束後凍結。之後只在實作或測試發現實際問題時修改。

## 文件中的兩種編號

**工作編號（P0–P7）**：規格內部用來安排工作的順序。每個編號完成時會建立一個對應的 Checkpoint Tag。

| 工作編號 | 內容 | Checkpoint Tag |
|---|---|---|
| P0 | 專案骨架、開發環境、容器 | `cp-0-foundation` |
| P1 | 規格、架構、驗收條件 | `cp-1-architecture-specs` |
| P2 | 帳號與登入（P2-A）、文件管理（P2-B）、文件入庫（P2-C）、問答（P2-D） | `cp-2-platform-rag-mvp` |
| P3 | 摘要、對話記憶、拒答 | `cp-3-document-qa` |
| P4 | 檢索評測 | `cp-4-rag-evaluation` |
| P5 | 完整介面與個人偏好 | `cp-5-platform-ui` |
| P6 | 整合、權限與一致性檢查 | `cp-6-stabilization` |
| P7 | 說明文件、Demo、簡報、打包 | `cp-7-final-delivery` |

**決策編號（D01、D02…）**：文中的「決策日誌 Dxx」指開發過程的內部決策紀錄，記載每個決定的討論經過。該紀錄與階段回顧等開發紀錄未隨此 repo 提供；架構層級的決定與理由見 `03-decisions/`。
