# ADR 0010：檢索參數——切塊 400、Top-K 5、維持 Vector；相似度門檻建議 0.50

- 狀態：切塊、Top-K、Vector 已採用（維持現值）；門檻改為 0.50 待使用者決定
- 日期：2026-11-07
- 對應決策日誌：D04、D07（參數由實驗決定）、D80（P4 題庫與實驗）
- 數據：`evaluation/retrieval-parameters/`（AC-19）；題庫 `evaluation/ground-truth/question-set.json`（AC-18）

## 背景

規格 02 §9 要求切塊大小、Top-K、是否 Hybrid、相似度門檻各有實驗數據。P2 以來的預設是 400 tokens（重疊 80）、K＝5、純向量、門檻 0.45，當時沒有數據。P4 以 19 題的題庫（必答 3、細節 4、表格數字 3、GraphRAG 論文 4、跨文件 2、無答案 3；證據為原文逐字、附頁碼）量測。

## 考慮過的選項與數據（K＝5，Vector；完整表見實驗 README）

|---|---|---|

| 400×5 | Recall | 命中率 | 關鍵字型 9 題 Recall |

## 決定

1. **切塊 400、重疊 80**：三者中 Recall 與命中率最高；256 把表格與定義段切散，600 每題多三成 tokens 卻沒有更高的涵蓋。
2. **Top-K 5**：K＝8 多 0.04 的 Recall 要多 49% 的證據 tokens，而那 0.04 正式程式已由「表格後文」補到（0.88）。
3. **維持 Vector，不採 Hybrid**：規格 §9.3 的採用條件是 Hybrid 涵蓋率高於 Vector 且正確性不下降；400×5 下 Hybrid 的 Recall 與命中率都較低，關鍵字型題目也沒有優勢。Hybrid 在 Q2、Q3 各把一段證據拉進前 5，但在 D3、G4 把導論頁擠進來。600×8 時 Hybrid 較高（0.89）但要 5,092 tokens。PostgreSQL 的 `simple` 設定不分中文詞、排序非嚴格 BM25，在報告中註明。
4. **門檻建議由 0.45 改為 0.50**：§9.5 的準則是誤拒為零且拒答率最高，0.50 三種切塊都是 3/3 與 0/15。餘裕只有 0.03 到 0.04、無答案題只有 3 題，所以列為建議，改不改由使用者決定；改的話同時更新 `.env.sample` 與規格的參數表。

## 後果

- 預設參數不變，但從此有數據可引用；`make eval` 約 30 秒可重跑。
- 已知的檢索缺口留在紀錄裡：Q2 的 Table 1 GraphRAG 區塊不在 Vector 前 5（navigate 模式的 Navigator 為此而設）；G2 的 Table 6 在第 26 頁，三種切塊都不在前 8；跨文件題 X1 前 5 只來自一份文件（Document-aware Retrieval 為選做）。
- 回答正確性沒有另跑實驗：最佳檢索組合就是現行預設，其回答正確性已有 `evaluation/navigator-abc/` 的百餘次真實模型紀錄；Hybrid 未達採用條件不另跑。這是規格 §9.7 允許的縮小規模，記於決策日誌 D80。
